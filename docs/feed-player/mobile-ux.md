# Feed Player Mobile UX (MVP)

## Цель
Зафиксировать единое мобильное поведение feed-player для разных форматов видео, чтобы:

- сохранить сцену без потерь;
- обеспечить предсказуемый UX для жестов и контролов;
- минимизировать риск перекрытия критичного контента кадра UI-элементами.

## 1) Mobile-режим отображения по aspect ratio

Базовый контейнер mobile feed-player: вертикальный viewport карточки (`portrait`), fit-режим по умолчанию — `contain`.

### 1.1 Вертикальные видео (`9:16`)
- Видео заполняет основной контейнер по высоте и ширине максимально полно.
- В нормальном случае черные поля отсутствуют.
- Допускаются минимальные технологические полосы только при технической несовместимости источника с точным `9:16`.

### 1.2 Горизонтальные видео (`16:9`, `21:9`)
- Видео показывается **целиком**, без обрезки сцены.
- Отображается по ширине контейнера.
- Сверху и снизу появляются полосы (`letterbox`), размер зависит от ratio:
  - `16:9` — умеренные полосы;
  - `21:9` — выраженные полосы.

### 1.3 Квадратные и промежуточные (`1:1`, `4:5`, `3:4`)
- Видео вписывается в контейнер без обрезки.
- Для `1:1` чаще заметны полосы сверху/снизу.
- Для `4:5` и `3:4` полосы меньше, но остаются допустимыми, если это нужно для сохранения полного кадра.

## 2) Приоритеты UI (фиксированный порядок)

При конфликтах решений используется строгий приоритет:

1. **Сохранение сцены** (никакой обрезки критичного контента в дефолтном режиме).
2. **Отсутствие полос** (предпочтительно, но не ценой п.1).
3. **Визуальная плотность** (максимальное заполнение экрана вторично относительно п.1 и п.2).

Следствие: если одновременно нельзя и сохранить сцену, и убрать полосы — полосы допустимы.

---

## 3) Gestures / Controls на mobile при наличии полос

Полосы считаются частью интерактивной зоны карточки и не должны «ломать» базовые жесты.

### 3.1 Tap по видео/полосам
- **Single tap** по любой точке карточки (включая полосы): показать/скрыть overlay-контролы.
- Если контролы уже видимы, tap вне активных кнопок — скрыть контролы по таймауту/повторному tap.

### 3.2 Pause / Play
- Tap по центральной области (или кнопке play/pause) переключает `play <-> pause`.
- При `paused` состояние должно быть явно обозначено (иконка/лейбл), независимо от наличия полос.

### 3.3 Mute / Unmute
- Кнопка mute фиксируется в верхней безопасной зоне (обычно правый верхний угол).
- Tap по mute работает одинаково в режимах без полос и с полосами.
- Состояние звука сохраняется между карточками в рамках текущей сессии (если это уже поддержано продуктом).

### 3.4 CTA «Полный фильм»
- CTA отображается как первичная action-кнопка в нижней безопасной зоне.
- При наличии нижней полосы CTA может располагаться на полосе, чтобы не закрывать контент кадра.
- Минимальная цель касания — не менее 44x44 pt.

### 3.5 Вертикальные жесты ленты
- Свайп вверх/вниз для смены карточки приоритетнее вторичных жестов на оверлеях.
- Интерактивные элементы (кнопки, слайдеры) должны перехватывать жест только в своей touch-области.

## 4) Расположение подписи и кнопок (защита критичной области кадра)

### 4.1 Безопасные зоны
- Верхняя безопасная зона: системный status bar + отступ.
- Нижняя безопасная зона: home indicator / системная навигация + отступ.
- Боковые отступы: не менее 12-16 pt от границ контейнера.

### 4.2 Правило размещения overlay
- Подпись, метаданные автора и secondary-кнопки размещаются в нижнем блоке.
- Primary CTA «Полный фильм» — под подписью или рядом, но в пределах нижней безопасной зоны.
- Если видео горизонтальное и есть нижняя `letterbox`-полоса, overlay приоритетно переносится на нее.
- Запрещено размещать ключевые элементы поверх центральной области кадра, где обычно находится главный объект сцены.

### 4.3 Адаптация по типу кадра
- `9:16`: overlay компактный, с градиентной подложкой внизу при необходимости контраста.
- `16:9`/`21:9`: часть UI можно вынести в верхнюю/нижнюю полосу.
- `1:1`/`4:5`/`3:4`: придерживаться нижней зоны, избегая перекрытия центральных 60% высоты кадра.

## 5) UX-скрин-таблица состояний

| Состояние | Видео | Полосы | Overlay/контролы | Пользовательские действия | Критерии качества |
|---|---|---|---|---|---|
| `loading` | Первый кадр еще не готов, показывается poster/skeleton в стабильном контейнере | По ожидаемому ratio контейнера; без layout shift | Минимум UI: loader + базовые системные отступы | Ожидание, tap игнорируется или открывает базовый overlay | Нет «прыжков» layout, нет мигания контейнера |
| `metadata-known` | Ratio определен, fit=`contain`, контейнер стабилен | Для `16:9`/`21:9` видны `letterbox`; для `9:16` обычно без полос | Появляются штатные контролы и подпись | Tap для показа/скрытия контролов | Корректный выбор режима без обрезки сцены |
| `playing` | Идет воспроизведение, сцена полностью видима | Допустимы по ratio | Контролы авто-скрываются, CTA доступен в нижней безопасной зоне | Tap, mute, переход по CTA, свайп ленты | Контент не перекрыт критично, UI читаем |
| `paused` | Кадр заморожен | Без изменений относительно `playing` | Явный индикатор pause + доступные action-кнопки | Resume по tap/play, CTA и mute активны | Понятная обратная связь состояния |
| `error` | Видео не воспроизводится, показывается fallback/poster | Не принципиально; контейнер остается стабильным | Error-state: текст + retry (если применимо) + CTA fallback | Retry, переход по CTA, свайп дальше | Нет краша UI, есть понятный путь действия |
| `low-bandwidth` | Пониженное качество/буферизация, приоритет непрерывности | Сохраняются по ratio | Индикатор degraded mode/буферизации без агрессивного перекрытия кадра | Пользователь может продолжить просмотр, pause, mute, CTA | UX остается управляемым, без потери основных контролов |

## Короткий итог

- На mobile в MVP работает безопасная стратегия `contain` и приоритет сохранения сцены.
- Полосы — допустимая цена за отсутствие обрезки.
- Жесты и контролы обязаны работать единообразно и на контенте, и в зонах полос.
- Overlay размещается через safe-area и, где возможно, уходит в полосы, чтобы не закрывать критичный контент кадра.
