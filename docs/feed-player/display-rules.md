# Feed Player: единые правила отображения видео (MVP)

## Цель
Зафиксировать единые правила отображения видео в ленте, чтобы:

- сохранять исходную сцену без потерь в MVP;
- исключить визуальные скачки интерфейса;
- обеспечить предсказуемое поведение на mobile и desktop;
- дать прозрачные критерии качества и дефектов.

## Поддерживаемые aspect ratio
Для MVP считаем поддерживаемыми и валидными следующие соотношения сторон источника:

- `9:16`
- `16:9`
- `1:1`
- `4:5`
- `21:9`
- `4:3`
- `3:4`

## MVP-принцип (mobile)
Базовый режим mobile-плеера:

1. По умолчанию используется `object-fit: contain`.
2. Обрезка сцены не допускается.
3. Черные поля (`letterbox`/`pillarbox`) допустимы и считаются корректным способом сохранить всю сцену.

### Запрещено в MVP
- Использовать `object-fit: cover` как дефолтное поведение.
- Обрезать значимую часть кадра ради заполнения контейнера.

### Допустимо в будущем (post-MVP)
- Режим user-toggle «Заполнить экран» с `cover` как **явный opt-in пользователя**.
- По умолчанию даже при наличии toggle остается безопасный режим `contain`.

## Desktop-принцип
Для desktop фиксируем:

1. **Стабильные контейнеры** вместо «плавающих» размеров.
2. **Выбор контейнера на основе метаданных** видео (aspect ratio), а не по факту первого отрисованного кадра.

Это снижает риск layout shift и делает поведение карточек/плеера предсказуемым.

## Поведение до получения метаданных
До момента, пока ratio не определен (metadata еще не загружены), используется безопасный fallback:

1. Рендерится стабильный placeholder фиксированного контейнерного типа (без layout shift).
2. Отображается `poster` (если доступен).
3. При отсутствии `poster` используется визуальный fallback (нейтральная заглушка).
4. После получения метаданных контейнер переключается только по заранее заданным правилам, без анимаций, вызывающих скачки layout.

## Таблица решений
> Принцип для MVP: fit mode = `contain` для всех ratio.

| Video ratio | Container type (desktop/mobile) | Fit mode (MVP) | Ожидаемые черные поля |
|---|---|---|---|
| `9:16` | Vertical container | `contain` | Обычно нет на vertical-контейнере; возможны `pillarbox` на более широком контейнере |
| `16:9` | Horizontal container | `contain` | `letterbox` при более высоком контейнере |
| `1:1` | Square container | `contain` | `letterbox` или `pillarbox` в зависимости от контейнера |
| `4:5` | Portrait container | `contain` | Небольшие `pillarbox`/`letterbox` в зависимости от контейнера |
| `21:9` | Cinematic-wide container | `contain` | Выраженные `letterbox` при стандартной высоте контейнера |
| `4:3` | Classic container | `contain` | `pillarbox` в широком контейнере; `letterbox` в высоком |
| `3:4` | Portrait-classic container | `contain` | Небольшие `pillarbox` в широком контейнере |

## Что считать дефектом
Критерии дефекта для feed player в MVP:

1. **Нежелательная обрезка сцен**
   - Любая обрезка контента в дефолтном режиме (без user-toggle) — дефект.
2. **Скачки layout**
   - Пересчет высоты/ширины карточки или плеера после загрузки метаданных, приводящий к заметному «прыжку» интерфейса — дефект.
3. **Выход UI за безопасные зоны**
   - Перекрытие или выход контролов/оверлеев/подписей за безопасные области экрана (особенно mobile) — дефект.

## Краткий итог
- В MVP приоритет — сохранение всей сцены (`contain`) и стабильность интерфейса.
- Черные поля — нормальное и ожидаемое поведение.
- `cover` возможен только как будущая пользовательская опция «Заполнить экран».
