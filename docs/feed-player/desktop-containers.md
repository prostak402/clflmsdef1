# Feed Player (desktop): контейнеры и правила выбора

## Цель

Зафиксировать единые контейнеры для desktop-ленты, правило выбора по `aspectRatio`, границы размеров и fallback-поведение, чтобы исключить визуальные скачки в feed.

## Типы контейнеров (desktop)

В desktop-сетке используются три канонических контейнера:

1. `vertical` — целевой формат `9:16`.
2. `universal` — универсальный формат для `4:5` и `1:1`.
3. `wide` — для `16:9` и более широких видео (`21:9` и т.п.).

## Правило выбора контейнера

Выбор контейнера выполняется по `aspectRatio = width / height` из метаданных видео.

Базовые пороги для MVP:

- `aspectRatio < 0.8` → `vertical`
- `0.8 <= aspectRatio <= 1.3` → `universal`
- `aspectRatio > 1.3` → `wide`

> Пороги считаются рабочими для MVP и должны быть дополнительно валидированы дизайном на реальных выборках контента.

## Размерные ограничения контейнеров в desktop-сетке

Для визуальной стабильности карточек фиксируются min/max размеры контейнеров.

| Container   | Aspect (target) | min-width | max-width | min-height | max-height |
| ----------- | --------------: | --------: | --------: | ---------: | ---------: |
| `vertical`  |          `9:16` |   `220px` |   `280px` |    `390px` |    `500px` |
| `universal` |   `4:5` / `1:1` |   `240px` |   `340px` |    `300px` |    `425px` |
| `wide`      |         `16:9+` |   `320px` |   `480px` |    `180px` |    `270px` |

Дополнительно:

- Размер контейнера выбирается в пределах этих границ по брейкпоинту сетки.
- После первичного выбора контейнера размер не должен «прыгать» при загрузке видео.

## Fallback при неизвестных размерах

Если `width/height` еще неизвестны (метаданные не загружены):

1. Временно используется контейнер `universal`.
2. Рендерится стабильный placeholder/`poster` в выбранной рамке.
3. После получения метаданных контейнер переопределяется по правилу `aspectRatio`.
4. Переключение выполняется с мягким переходом (короткий fade/resize transition без layout shift карточек соседних элементов).

## Совместимость с `PlayerCard` и lazy-rendering

- Правило выбора контейнера применяется на уровне `PlayerCard` до старта воспроизведения.
- При lazy-rendering (виртуализация/отложенный mount) контейнер должен резервировать финальное место в сетке заранее.
- Если карточка размонтирована и смонтирована повторно, используется последнее известное значение `aspectRatio`; при его отсутствии повторяется fallback через `universal`.
- Политика не конфликтует с MVP-правилом `object-fit: contain` из `display-rules.md`.
