# MVP Readiness Checklist (pre-backend)

Краткий чеклист готовности ключевых пользовательских сценариев до подключения реального backend.

## Связанные документы

- [Auth MVP model](./auth-mvp-model.md)
- [Mock → API migration map (task-020)](./task-020-mock-to-api-migration-map.md)

## Обязательные флоу и критерии готовности

### 1) Auth → Genres onboarding

**Готово, если пользователь может:**

- зарегистрироваться/войти через текущую MVP auth-модель;
- пройти onboarding с выбором жанров;
- после завершения onboarding попасть в основной feed без ручных обходов.

**Не готово, если:**

- вход/регистрация нестабильны или требуют «технических» шагов;
- выбранные жанры не сохраняются в рамках сессии и не влияют на стартовый контент;
- есть блокирующие ошибки в переходе из onboarding в feed.

### 2) Feed

**Готово, если пользователь может:**

- открыть feed после onboarding;
- видеть список карточек контента в ожидаемом порядке;
- обновить экран и получить консистентный результат для mock-состояния.

**Не готово, если:**

- feed не открывается из основного пользовательского пути;
- список пустой/ломается без понятного пользователю состояния;
- навигация из feed в детали контента нестабильна.

### 3) Like / Bookmark / Comment

**Готово, если пользователь может:**

- поставить/снять like;
- добавить/убрать bookmark;
- добавить комментарий и увидеть его в интерфейсе;
- после базового рефреша экрана увидеть ожидаемое состояние для текущего pre-backend режима.

**Не готово, если:**

- действия не дают явной обратной связи;
- состояния like/bookmark/comment теряются сразу после действия;
- есть критичные расхождения между UI и mock-данными.

### 4) Profile

**Готово, если пользователь может:**

- открыть свой профиль из основного пользовательского маршрута;
- увидеть базовую информацию профиля и ключевые пользовательские артефакты (например, bookmarks/активность);
- редактировать доступные в MVP поля без блокирующих ошибок.

**Не готово, если:**

- профиль недоступен из основного flow;
- отображаются неконсистентные данные о пользователе;
- сохранение изменений в профиле не подтверждается UI.

### 5) Admin moderation

**Готово, если администратор может:**

- открыть moderation-зону;
- просмотреть список сущностей на модерацию;
- выполнить базовое действие модерации (approve/reject) и увидеть изменение статуса.

**Не готово, если:**

- недоступен вход в admin-сценарий;
- модерационные действия не меняют состояние сущности в UI;
- отсутствует понятная обратная связь об успешности/ошибке действия.

## Что явно НЕ входит в pre-backend этап

- Персонализированные рекомендации v2 (ML/поведенческая персонализация).
- Billing/платежи/подписки.
- Production-ready auth (боевые провайдеры, hardening, security/compliance).
- Реальные интеграции с внешними сервисами (email/SMS/push провайдеры и т.д.).
- Полноценные SLA/SLO, observability и эксплуатационные процедуры production-уровня.
