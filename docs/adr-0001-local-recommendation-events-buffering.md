# ADR-0001: Локальная модель recommendation events (без серверной отправки)

## Статус

Accepted

## Контекст

На текущем этапе продукта аналитические recommendation/feed события нужны для унификации клиентского контракта, UI-инструментации и тестирования схемы, но серверный ingestion pipeline ещё не подключён.

## Решение

Используем локальную модель событий в клиенте:

- события создаются через `feedService.trackEvent(name, payload)`;
- обязательный envelope (`eventId`, `schemaVersion`, `ts`, `sessionId`, `userId`) добавляется автоматически;
- события пишутся в in-memory буфер;
- `feedService.flush()` возвращает накопленные события и очищает буфер;
- часть дедупликации выполняется на клиенте (`clip_impression`, `clip_view_threshold`).

## Последствия

- Плюсы: детерминированные unit/integration тесты, прозрачная трассировка UI → событие, готовность к будущему бэкенд-коннектору.
- Ограничения: после перезапуска страницы буфер теряется; нет гарантированной доставки/ретраев в сеть.

## Changelog

- 2026-02-24: Подтверждено, что для recommendation/feed используется локальная событийная модель без server ingestion: события буферизуются в памяти и отдаются наружу только через `feedService.flush()`.
